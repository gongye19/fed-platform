# 项目目标

- 当前版本依据：截至 2026-09-11 已确认的产品决策
- 最后复核时间：2026-09-11

## G 总目标

建设一套面向多个自研应用的通用多站点联邦平台：每个应用拥有独立联邦域和 Agent，平台统一完成可信收集、联邦生成、版本溯源、定向下发、站点采用状态与效果展示，而不限定联邦对象或算法。

## 项目边界

- 范围内：FedApp 契约、应用与站点身份、工件通道、应用独立 Agent 与算法、版本和下发、评测回传、管理控制台、PostgreSQL/S3 存储。
- 范围外：应用内部业务、原始私有数据处理、站点是否采用候选版本、应用镜像部署和站点基础设施运维。

## 明确不做

- 不为不遵循 FedApp 契约的历史应用增加兼容层。
- 不允许插件直接访问平台数据库、站点凭据或绕过发布状态机。
- 不为尚未出现的需求增加插件市场、消息队列或跨云双写。

## 验收标准

### C1

- 标准：每个应用自动拥有且仅拥有一个相互隔离的联邦域和 Agent。
- 判定方法：注册两个应用并验证跨应用凭据、工件和版本访问均被拒绝。
- 最低通过线：数据库约束和 API 测试同时通过。
- 当前版本依据：初始定义。
- 状态：部分验收。

### C2

- 标准：站点可凭应用密钥幂等上传贡献与评测，内容和元数据完整保存。
- 判定方法：重复上传、错误摘要、错误版本和错误应用分别执行集成测试。
- 最低通过线：合法请求不丢不重，非法请求被拒绝。
- 当前版本依据：初始定义。
- 状态：部分验收。

### C3

- 标准：应用独立 Agent 可把所选站点数据和现有联邦版本交给应用算法，生成可追溯的不可变版本。
- 判定方法：检查生成任务、基础版本、输入 Submission、输出 Artifact 和 Release 谱系。
- 最低通过线：完整链路可运行且不同应用不可串用插件状态。
- 当前版本依据：初始定义。
- 状态：已由 Fed-EvoMed 单应用验证。

### C4

- 标准：任一联邦版本可定向下发到任意有权限站点，站点可暂存、采用、拒绝或回退并独立上报当前版本。
- 判定方法：执行 stage、activate、reject、rollback、ack 和 status 流程。
- 最低通过线：下发状态与实际采用状态不混淆，历史可审计。
- 当前版本依据：初始定义。
- 状态：部分验收。

### C5

- 标准：控制台以应用为边界展示站点、应用版本、联邦版本、效果、时间线和日志，并允许显式选择生成输入和下发目标。
- 判定方法：构建测试及浏览器端到端检查。
- 最低通过线：不暴露内部 UUID 等无决策价值字段，不默认替用户选择生成或下发对象。
- 当前版本依据：初始定义。
- 状态：已实现，待正式浏览器验收。

### C6

- 标准：第二个遵循 FedApp 契约的新应用只新增应用清单和算法实现即可接入，不修改平台核心通道。
- 判定方法：第二个应用通过 conformance test 并完成一次端到端联邦。
- 最低通过线：平台协议、数据库实体和传输流程无需应用特化修改。
- 当前版本依据：初始定义。
- 状态：未验收。
